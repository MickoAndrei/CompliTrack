## Confirmed causes and resulting behavior

1. **CAR state disagreement.** The old `CorrectiveActionPresenter` replaced Open/In Progress with Awaiting Verification when a response or an auditee-uploaded linked file had a sufficiently recent timestamp. It did not require a recorded state transition or permitted corrective-evidence context. Other serializers, timelines and transitions continued using the stored state. The projection has been removed. `CarStatus` normalizes recognized spelling aliases only; API rows, lists, metrics and timelines use that canonical state. Raw stored states/history are retained. Unknown states remain unknown, explain the issue, and permit only assigned-auditor reopening with a reason. New transition events retain the raw previous state. Explicit verification/closure permissions and assignment/department checks remain mandatory. Upload/reference submissions do not close CARs.

   Read-only inspection of the configured database confirmed `DEMO-CHK-ENG-PROGRESS` stores `in_progress`, has one In Progress history entry, zero evidence responses and one linked file whose uploader/department match the auditee. The Auditor role currently has neither `cars.verify` nor `cars.close`. The timestamp-derived label was a defect; denial of closure without those grants is intentional. The detail view now explains the required configured authority. No grant or record was changed by inspection.

2. **Submission readiness.** `AuditChecklist` previously examined only saved checklist items. The current request and its latest response were ignored, so an earlier item-level review could coexist with a newly submitted, unreviewed response. Readiness now reports checklist gaps separately from outstanding requests and links to Evidence Requests. Every request must be reviewed, with the latest response carrying its own completed review. Requested, Needs Information, unknown and unreviewed states block submission. The server rechecks current data and retains optimistic version protection. Physical originals and document references remain supported. No cancellation workflow was invented; this workflow requires requests to be completed through review.

   Read-only inspection confirmed `IQA-2026-0002` is stored as `ready`, with two checklist items and a `response_submitted` evidence request.

3. **Plan selection.** Preparation previously offered every accessible archive. Existing categories describe organizational filing and presentation methods (`file`, `digital-reference`, `physical-original`), not a reliable audit-plan purpose. New selections default to documents with an explicit, version/checksum-bound audit-plan classification. Legacy/unclassified records appear only after an explicit opt-in. An authorized ATL must confirm the actual controlled document and give a classification reason; the backend checks ownership, controlled reference, actor access and classification metadata. Selectors show code, title, presentation type and version. Classification and prior classification are recorded. Existing approved plans and assignment snapshots are neither renamed nor detached; incomplete legacy classification is explained and must be confirmed during revision.

4. **Independence reference.** Any nonempty string, including `none`, previously passed validation. UI and API now reject placeholder-only references. Submit and approval revalidate saved metadata. New assignments cannot rely on a placeholder legacy procedure. Existing approvals and existing assignments retain their histories/snapshots and show a legacy warning. The exact configurable `audit_plans.approve` capability is unchanged; no institutional exception or approver was invented.

5. **Annual reporting.** `/api/v1/reports?annual=1&year=2026&planId=...` adds an annual projection while preserving the existing default report API for current consumers. `/admin/reports` provides year/plan controls, streamed CSV and browser printing. The assignment unit scope is used, including the five CET departments and Office of the Dean when applicable; the older academic-department directory deliberately excludes the Dean and is not reused for this report. Audit records remain restricted to the ATL reviewer; plan metadata is restricted to authorized reviewers or their scoped assignments. JSON and CSV use the same service and filters.

   Planned means unit/plan coverage for plans whose date ranges overlap the year. Assigned includes all current lifecycle states; Submitted, Returned and Accepted/Completed are current-state counts. Scheduled audit dates select the year. C/N/O come only from accepted checklists; compliance is `C / (C + N)` and is **Not yet assessed** when C+N=0. Observations remain separate. CAR metrics include open, overdue, awaiting verification, closed and unknown states, plus outstanding request work. Checklist-linked CARs follow selected audits; standalone legacy checks use their creation year and have no plan attribution. Legacy checks and CARs never add to checklist C/N/O. CAR closure cannot rewrite original findings. CSV includes scope/denominator notes and spreadsheet-formula protection.

6. **Terminology.** `AuditStatus` distinguishes lifecycle labels from checklist readiness and request review. Stored `ready` remains compatible but displays In Progress; Ready to submit is exclusively a readiness result. `accepted` displays Accepted / Completed. Requests display Response Submitted — Awaiting Auditor Review or Response Reviewed, separately from audit review. Filtering uses stored values, including the compatible `under_review` request filter, rather than comparing display labels. Notification event types retain compatibility.

7. **Dates.** Shared PHP, JavaScript and Dart formatters display instants in Asia/Manila, identify PST/UTC+08:00 and retain seconds in histories. Calendar-only dates retain their literal day. Stored timestamps and historical instants remain UTC. Plan history retains exact ISO values in datetime/title attributes. The Flutter CAR board and finding history use the shared formatter.

8. **Documents.** Details dialogs open immediately with loading, failure and retry feedback. Late document/folder detail responses cannot replace newer selections or reopen closed dialogs; existing list navigation cancellation was already implemented and was preserved. Refresh feedback is immediate. Folder menus have explicit per-folder accessible names, Escape handling and focus return. Names/owners have focusable full-value discovery; filename truncation avoids character-by-character wrapping. Permission choices include the existing authorized user code or account identifier, without expanding account visibility. Navigation consistently says My Drive. Existing role help links now target the supported Documents routes. The walkthrough's exact claim of absent accessible names was not independently reproduced: source buttons already had visible text; explicit names and keyboard behavior were strengthened.
